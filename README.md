# JiYu Attack Next

极域学生端 UDP 控制报文测试工具，提供 PySide6 图形界面和命令行脚本两种使用方式，可打包为 Windows EXE。

| 项目         | 说明                                                                    |
| ------------ | ----------------------------------------------------------------------- |
| 上游仓库     | [ht0Ruial/Jiyu_udp_attack](https://github.com/ht0Ruial/Jiyu_udp_attack) |
| 图形界面 | [gui.py](gui.py)；可构建为 `dist/JiyuUdpTest.exe` |
| 命令行入口 | [main.py](main.py) |
| 运行环境 | Python 3.13；本机信息查询及防火墙相关功能依赖 Windows 命令 |
| 默认通信方式 | UDP，目标端口 `4705`                                                    |

## 项目来源

本项目的上游仓库为 [ht0Ruial/Jiyu_udp_attack](https://github.com/ht0Ruial/Jiyu_udp_attack)。原始项目及相关说明请参阅上游仓库。

命令行入口为 **`main.py`**，图形界面入口为 **`gui.py`**。两者共用报文处理与发送逻辑，参数默认值与执行行为以当前仓库代码为准。

使用前，请确认已获得相应网络环境与设备的测试授权。

## 图形界面

### 直接运行 Python 版本

在项目根目录打开 PowerShell，安装依赖并启动：

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python gui.py
```

也可以执行 `powershell -ExecutionPolicy Bypass -File .\run_gui.ps1`，由启动脚本自动使用项目虚拟环境。界面包含“发送测试”和“本机工具”两个工作区，提供消息与命令编辑、文件导入、循环发送、设备操作、日志查看与导出。

### 运行打包后的 EXE

已构建的文件位于：

```text
dist\JiyuUdpTest.exe
```

直接双击即可运行，无需安装 Python 或 PySide6。EXE 为单文件窗口程序，首次启动会解压运行时资源，可能需要数秒。

### 界面行为说明

- 发送与取消按钮固定在窗口底部。任务在后台执行，可查看日志、请求取消；关闭窗口时会先结束当前任务再退出。
- 消息支持多行和长文本自动分条。每条报文最多 448 个 UTF-16 单元，分条后的消息由接收端独立显示，脚本不负责合并或确认送达。
- 消息、命令与重启或关机指令可以组合发送。界面只允许重启与关机二者选一。
- 命令最多容纳 163 个 UTF-16 单元，界面实时显示使用量；超过容量会提示错误。
- “本机工具”只操作运行程序的电脑，不向目标发送报文。防火墙操作需要管理员权限。
- 反向 Shell 功能保留在 CLI 的 `-e nc` 中，GUI 不提供对应入口。
- 日志中的“发送完成”只表示本机发送调用完成，不代表目标已收到或执行成功。

## 命令行脚本

原有的 CLI 脚本仍保留，可在不启动 GUI 的情况下使用。

项目使用 Python 3.13 虚拟环境，可先激活：

```powershell
.\.venv\Scripts\Activate.ps1
```

首次克隆后的环境创建方法、GUI 依赖和中文提交规范见 [开发与提交规范](CONTRIBUTING.md)。

**查看命令行帮助：**

```powershell
python main.py -h
```

**命令格式：**

```text
python main.py -ip <目标地址> [-p <目标端口>] <功能参数>
```

向目标发送报文时需要指定 `-ip`；`-p` 未指定时使用 `4705`。本地功能 `-e g`、`-e break` 和 `-e continue` 不需要目标地址。需要图形界面时运行 `python gui.py`。

## 编译为 EXE

### 环境准备

确认 Python 和虚拟环境可用，并安装开发依赖：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

### 一键构建

在项目根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

需要清理 PyInstaller 缓存后重新构建时使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Clean
```

构建脚本会读取 [JiyuUdpTest.spec](JiyuUdpTest.spec)，使用项目虚拟环境中的 PyInstaller 生成单文件、无控制台窗口的 `dist\JiyuUdpTest.exe`。中间文件写入 `build\`，转换后的图标写入 `assets\app.ico`。构建目录、产物和生成的图标已被 `.gitignore` 排除。

如果 PowerShell 拒绝执行脚本，可使用上面的 `-ExecutionPolicy Bypass` 参数；无需永久修改系统执行策略。构建需要当前用户可以读取已安装的 PySide6 和 PyInstaller。

### 分发说明

`dist\JiyuUdpTest.exe` 可以单独分发。首次运行的电脑无需安装 Python。构建前应关闭正在运行的同名程序，避免文件被占用；项目生成的是未签名 EXE，正式发布时可自行签名。

## 参数参考

### 通用参数

| 参数            | 类型   | 默认值 | 用途与说明                                             |
| --------------- | ------ | ------ | ------------------------------------------------------ |
| `-h` / `--help` | 开关   | 无     | 显示帮助并退出                                         |
| `-ip`           | 字符串 | 无     | 指定目标地址，支持单个 IPv4、同网段末段范围及 `/24`    |
| `-p`            | 整数   | `4705` | 指定目标 UDP 端口                                      |
| `-msg`          | 字符串 | 无     | 发送文本消息，保留多行内容；超长文本自动分条发送 |
| `--msg-file` | 路径 | 无 | 从 UTF-8 文件读取消息；`-` 表示读取标准输入；与 `-msg` 互斥 |
| `-c`            | 字符串 | 无     | 向目标发送待执行的命令                                 |
| `-l`            | 整数   | `1`    | 指定发送轮数；每轮遍历全部目标与报文                   |
| `-t`            | 整数   | `22`   | 指定发送轮次之间的等待时间，单位为秒；仅多轮发送时生效 |
| `-e`            | 枚举   | 无     | 选择扩展功能，取值见下表                               |

### 扩展功能

| 参数组合      | 功能                               | 执行范围       | 条件与说明                                                                  |
| ------------- | ---------------------------------- | -------------- | --------------------------------------------------------------------------- |
| `-e r`        | 发送重启指令                       | 目标设备       | 需要指定 `-ip`                                                              |
| `-e s`        | 发送关机指令                       | 目标设备       | 需要指定 `-ip`                                                              |
| `-e g`        | 查询本机 IP 与学生端可能的监听端口 | 本机           | 尝试匹配 `Student` 相关进程及端口；不需要 `-ip`                             |
| `-e nc`       | 反向 Shell 连接                    | 本机与目标设备 | 需要 `-ip`；依赖外部 PowerShell 脚本下载与回连连通性                        |
| `-e break`    | 尝试阻断学生端网络连接             | 本机           | 修改 Windows 防火墙设置及名为 `StudentMain.exe` 的现有规则，需要管理员权限  |
| `-e continue` | 将学生端防火墙规则改为允许         | 本机           | 修改名为 `StudentMain.exe` 的现有规则，需要管理员权限；不还原全部防火墙设置 |

## 目标地址格式

| 格式       | 参数示例             | 目标范围                                |
| ---------- | -------------------- | --------------------------------------- |
| 单个地址   | `-ip 10.49.151.29`   | 仅 `10.49.151.29`                       |
| 同网段范围 | `-ip 10.49.151.1-10` | `10.49.151.1` 至 `10.49.151.10`，含两端 |
| `/24` 网段 | `-ip 10.49.151.0/24` | `10.49.151.1` 至 `10.49.151.254`        |

范围写法的右侧仅填写末段数字；当前实现仅支持 `/24` 网段格式，不支持任意 CIDR 前缀。地址会经过 IPv4 格式校验，范围或网段无效时会直接提示错误。

## 使用示例

示例中的 `10.49.151.29` 为占位目标地址，运行前请按实际测试环境替换。

### 发送文本消息

```powershell
python main.py -ip 10.49.151.29 -msg "Hello"
```

### 发送多行文本

使用 PowerShell 的 Here-String，可保留换行、空行与缩进：

```powershell
$message = @'
第一行通知
第二行通知

第四行通知
'@
python main.py -ip 10.49.151.29 -msg $message
```

脚本保留传入字符串中的真实换行，不会自动将字面量 `\n` 转成换行。目标端是否按多行显示，仍取决于学生端消息窗口的实现。

### 从文件读取长文本

将文本保存为 UTF-8 编码文件，可包含多行内容、空行及中文，也支持带 BOM 的 UTF-8 文件。

```powershell
python main.py -ip 10.49.151.29 --msg-file "notice.txt"
```

`--msg-file -` 可从标准输入读取文本。文件或标准输入适合较长内容，可避免将全文放入命令行参数；`--msg-file` 与 `-msg` 不可同时使用。

### 消息容量与分条行为

旧实现的消息模板为 954 字节，正文从偏移 56 开始，最多可写入 898 字节，即 **449 个 UTF-16 单元**；写满时没有为字符串结束符预留空间，超过容量会发生越界异常。这是发送缓冲区的容量，并非已验证的学生端显示上限。

当前实现保留原报文大小，每条为结束符预留 2 字节，正文最多为 **896 字节，即 448 个 UTF-16 单元**。普通中文、英文字母通常占 1 个单元，部分字符占 2 个单元；换行符也计入容量。

总文本不设固定长度上限，超出单条容量时自动拆成多条独立消息，并保留文本内容及换行，不拆开单个 Unicode 码点。总长度仍受可用内存及输入方式限制，文本不支持内嵌 NUL 字符。

**分条不等于接收端合并。** 脚本按顺序发送各条报文，但不提供接收端重组、回执或重传机制，不能保证长文本在目标端完整、有序地显示为同一条消息。

### 指定目标端口

```powershell
python main.py -ip 10.49.151.29 -p 4705 -msg "Test message"
```

### 发送查询命令

```powershell
python main.py -ip 10.49.151.29 -c "cmd.exe /c ipconfig"
```

### 使用包含空格的路径

在 PowerShell 中，可用外层单引号包裹整个命令，并用内层双引号包裹路径。

```powershell
python main.py -ip 10.49.151.29 -c 'cmd.exe /c dir "C:\Program Files"'
```

### 查询本机信息

```powershell
python main.py -e g
```

该功能仅查询运行脚本的本机，不查询远程目标。若未匹配到学生端进程或端口，输出可能不完整。

### 控制发送轮数与间隔

以下命令发送 3 轮消息，相邻两轮之间等待 10 秒，最后一轮结束后不再等待。

```powershell
python main.py -ip 10.49.151.29 -msg "Test message" -l 3 -t 10
```

### 组合发送消息与命令

```powershell
python main.py -ip 10.49.151.29 -msg "Test" -c "cmd.exe /c ipconfig"
```

每轮按消息、命令、重启或关机报文的顺序发送；实际是否执行及执行顺序由目标端决定。

### 发送重启或关机指令

以下为两条独立命令，按实际需求选择。

```powershell
# 重启目标
python main.py -ip 10.49.151.29 -e r

# 关闭目标
python main.py -ip 10.49.151.29 -e s
```

## 行为与限制

- **发送结果**：脚本不接收目标执行回执。“发送成功”仅表示本机发送调用未报错，不能据此确认目标已收到报文或完成操作。
- **循环参数**：`-l` 使用正整数，`-t` 使用非负整数。等待发生在两轮之间，不在每台设备之间。
- **功能组合**：`-msg`、`-c` 可与 `-e r` 或 `-e s` 组合。本地功能 `g`、`break`、`continue` 执行后退出；`nc` 使用独立分支，不处理同时传入的 `-msg` 或 `-c`。
- **文本编码**：消息与命令按 `utf-16le` 编码。消息超长时自动分条，命令仍受固定报文缓冲区限制；路径和引号仍需符合目标命令解释器的规则。
- **输出范围**：使用 `-c` 不会自动将目标命令的标准输出返回到当前终端。

## 问题排查

| 现象                            | 可能原因                                                   | 检查建议                                            |
| ------------------------------- | ---------------------------------------------------------- | --------------------------------------------------- |
| 提示找不到脚本文件              | 终端不在脚本目录，或仍使用旧文件名                         | 检查当前目录及文件名，统一使用 `python main.py ...` |
| 提示“发送成功”，目标无响应      | 地址或端口不匹配、报文被拦截、学生端未监听、目标未执行指令 | 核对目标地址、UDP 端口、学生端状态及目标端执行结果  |
| 包含空格的路径处理失败          | 路径未完整加引号，或引号在终端传参时发生变化               | 参考包含空格路径的示例，并核对目标端路径            |
| `-e g` 未显示端口 | 未找到 `Student` 相关进程或其 UDP 监听端口 | 在本机核对进程与监听状态；查询失败时会显示错误原因 |
| 只有 IP、没有功能参数时无法发送 | 没有生成任何待发送报文                                     | 指定 `-msg`、`-c` 或相应扩展功能                    |
| 长命令报错 | 命令超过固定报文缓冲区容量 | 缩短命令，检查终端输出的异常信息 |
| 长消息只显示部分内容或顺序不一致 | 消息被拆成独立报文，未提供接收端重组与可靠交付机制 | 核对目标端实际显示结果；分条发送不能保证合并为单条消息 |
| `--msg-file` 无法读取 | 文件不存在或文件编码不是 UTF-8 | 核对路径，将文件保存为 UTF-8 编码 |
