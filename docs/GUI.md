# GUI 使用说明

## 直接运行 Python 版本

在项目根目录打开 PowerShell，安装依赖并启动：

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m app.gui
```

也可以执行 `powershell -ExecutionPolicy Bypass -File .\scripts\run_gui.ps1`，由启动脚本自动使用项目虚拟环境。

界面使用 [PySide6-Fluent-Widgets](https://github.com/zhiyiYo/PyQt-Fluent-Widgets/tree/PySide6) 构建，采用 Fluent 侧边导航和统一圆角分区卡片，并按功能分为以下页面：

该组件库采用 GPLv3 与商业许可双授权。个人或非商业使用遵循项目随附许可条款；商业分发前请核对上游仓库的授权要求。

| 页面 | 主要用途 |
| --- | --- |
| 文本消息 | 编辑、导入和保存多行消息，发送自动分条的文本报文 |
| 远程命令 | 编辑并发送单条远程命令，实时显示缓冲区容量 |
| 设备操作 | 选择重启或关机，并在发送前预览解析后的目标设备 |
| 文件传送 | 选择本机任意文件，通过目标学生端下载到其当前用户桌面 |
| 设备备注 | 为 IPv4 地址添加可修改的备注名，并可直接设为当前目标 |
| 本机信息 | 查询运行程序的电脑 IP，以及 Student 相关监听端口 |
| 防火墙 | 修改 `StudentMain.exe` 的现有防火墙规则并查看逐项结果 |
| 运行日志 | 按功能、级别和关键词筛选，勾选导出或删除日志，并取消正在发送的任务 |
| 设置 | 切换主题、设置本次运行日志等级，恢复默认连接参数 |
| 关于 | 查看作者、GitHub 仓库、上游仓库和组件版本 |

目标地址按 IPv4 四段分开填写，段间自动以 `.` 连接；前三段分别填写 0–255，最后一段支持单个末段、末段范围（如 `1-10`）和 `/24` 网段（如 `0/24`）。在四个地址输入框中按回车会依次跳到下一段，在最后一段按回车会进入端口输入框。目标地址和 UDP 端口在文本消息、远程命令、设备操作与文件传送之间同步；发送轮数和轮次间隔仅在前三个远程页面之间同步。消息、命令及设备选择分别保留，切换页面不会清空草稿。窗口较窄时侧边栏会收窄为图标，窗口最小尺寸为 960 × 640。

## 文件传送

“文件传送”页面把本机任意路径的文件发送到目标电脑的当前用户桌面：

1. 填写单个目标 IPv4 地址或选择设备备注；文件传送不支持末段范围和 `/24` 网段。
2. 点击文件夹按钮选择文件，页面显示文件名、完整路径和大小。
3. 点击“传送文件”，确认目标与文件后开始任务。目标端通过 Windows 自带的 `curl` 下载，进度显示在页面和运行日志中。

传送时 GUI 自动检测发送端 IP（优先使用到目标的出口 IP），并启动一个仅在本机任务期间存在的随机令牌 HTTP 服务；界面不提供发送端 IP 输入框。目标电脑必须能访问该 IP 与临时端口，且允许执行远程命令。目标保存到当前登录用户桌面，不自动打开文件，也不会回传执行结果。

目标端不使用 PowerShell，因此不需要修改 PowerShell 执行策略。如果目标无法访问发送端、系统防火墙拦截监听端口或下载失败，页面会显示超时或下载失败。任务可取消；取消或超时后会停止临时文件服务。

## 设备备注

“设备备注”页面用于把常用的 IPv4 地址映射为易读名称：

1. 填写备注名和 IP 地址，点击“添加备注”。IP 地址同样分为四段，支持单个 IPv4、末段范围（如 `1-10`）和 `/24` 网段；备注名输入框按回车会进入地址第一段，地址最后一段按回车会保存。
2. 选中表格中的备注，可执行“设为当前目标”“修改”或“删除”；双击行也可直接修改。
3. 在任意远程页面点击目标地址右侧的“选择设备”，从弹窗的下拉列表中选择备注；目标地址四段会填入解析后的 IPv4，下方显示“备注名 → IPv4”的解析结果。
4. 修改备注名或 IP 后，当前目标如果引用该备注，会自动同步；删除正在引用的备注会清空当前目标。

备注名不区分大小写，不能为空、不能用纯 IP 格式，且同一名称只能对应一个地址或地址范围。备注可保存单个 IPv4、末段范围或 `/24` 网段；目标地址框仍可手动输入这些格式。备注与运行日志保存在程序所在目录的 `JiYuAttackNextData` 子文件夹中（源码运行时为项目根目录），重启 GUI 后仍会保留。只把 EXE 移到其他位置、不一起移动该文件夹时，会按默认配置启动。实际发送、确认框和设备预览始终使用解析后的地址，日志会记录备注名及解析结果。

## 运行打包后的 EXE

已构建的文件位于：

```text
output\JiYuAttackNext.exe
```

直接双击即可运行，无需安装 Python 或 PySide6。EXE 为单文件窗口程序，首次启动会解压运行时资源，可能需要数秒。

程序首次写入备注或日志时，会在 EXE 所在目录创建 `JiYuAttackNextData` 子文件夹，其中 `settings.ini` 保存设备备注，`runtime.log` 保存运行日志。若 EXE 所在目录不可写，备注和日志会保存失败并在界面提示；请将 EXE 放到可写目录后运行。

## 界面行为说明

- 每个页面底部固定显示状态、日志入口、取消操作和当前页面的主操作按钮。任务在后台执行，可查看日志、请求取消；关闭窗口时会先结束当前任务再退出。
- 消息支持多行和长文本自动分条。每条报文最多 448 个 UTF-16 单元，分条后的消息由接收端独立显示，脚本不负责合并或确认送达。
- 每个页面只发送当前页面的内容，避免切换页面后把不相关的草稿一起发送。重启与关机只能选择一项。
- 命令最多容纳 163 个 UTF-16 单元，界面实时显示使用量；超过容量会提示错误。
- “本机信息”和“防火墙”只操作运行程序的电脑，不向目标发送报文。防火墙操作需要管理员权限。
- 发送设备指令前会显示目标数量、端口和操作类型并要求二次确认。
- 反向 Shell 功能保留在 CLI 的 `-e nc` 中，GUI 不提供对应入口。
- 日志中的“发送完成”只表示本机发送调用完成，不代表目标已收到或执行成功。
- “关于”页顶部的图片与项目名称区域不绘制圆角卡片背景；下方作者、GitHub 仓库、上游仓库和组件版本仍分别显示独立圆角信息卡片。
- 运行日志默认以 `INFO` 等级运行，可在“设置”页的“运行日志等级”下拉框中切换为 `DEBUG`、`INFO`、`WARNING` 或 `ERROR`。运行等级是写入阈值：选择 `WARNING` 后，新的 `DEBUG`、`INFO` 记录不会进入列表和日志文件；本次运行结束后不会持久化该设置。
- 日志页提供两级筛选：“全部功能”按功能分类筛选，“全部级别”按 `DEBUG`、`INFO`、`WARNING`、`ERROR` 精确筛选，搜索框会在时间、级别、功能、内容、线程和输出位置中匹配关键词。多个筛选条件同时生效。
- 日志表每行带复选框，可多选；表头第一格（时间列之前）同样带复选框，用作全选。勾选表头复选框会选中当前筛选结果；任意一行取消勾选后表头复选框自动取消勾选；取消表头复选框会清空全部选择（包括被筛选条件隐藏的行）。批量操作只能针对已勾选的记录。
- 日志页上方的导出和删除按钮只作用于勾选记录：导出按钮按规范文本导出选中日志，删除按钮在确认后删除选中记录并同步重写日志文件；没有勾选记录时两个按钮均不可用。
- 运行日志在启动时从 `runtime.log` 载入最近 2000 条记录，新记录实时追加。日志文件采用规范文本格式，示例：`2026-10-23 12:34:56.789 [12345] [MainThread] INFO    app.gui.app.MainWindow:123 - [文本消息] 开始发送：192.168.1.20，端口 4705，1 轮`；多行内容与异常堆栈以缩进续行写入。旧版 JSONL 日志会自动读取并迁移为规范文本。
- 日志字段包括毫秒级本地时间、线程 ID、线程名称、级别、输出模块与行号、功能分类、消息和可选详情。异常会记录异常消息与 Python 堆栈，便于复现和定位问题。
