## 运行 Python 版本

在项目根目录安装依赖并启动：

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m app.gui
```

也可执行 `powershell -ExecutionPolicy Bypass -File .\scripts\run_gui.ps1`，由启动脚本自动使用项目虚拟环境。

界面使用 [PySide6-Fluent-Widgets](https://github.com/zhiyiYo/PyQt-Fluent-Widgets/tree/PySide6) 构建，采用 Fluent 侧边导航和统一圆角分区卡片。

## 功能页面

| 页面 | 主要用途 |
| --- | --- |
| 文本消息 | 编辑、导入和保存多行消息，发送自动分条的文本报文 |
| 远程命令 | 编辑并发送单条远程命令，实时显示缓冲区容量 |
| 设备操作 | 选择重启或关机，并在发送前预览解析后的目标设备 |
| 文件传送 | 勾选待传送文件或文件夹树，通过目标学生端下载到其当前用户桌面 |
| 设备备注 | 为 IPv4 地址添加可修改的备注名，并可直接设为当前目标 |
| 本机信息 | 查询运行程序的电脑 IP，以及 Student 相关监听端口 |
| 防火墙 | 修改 `StudentMain.exe` 的现有防火墙规则并查看逐项结果 |
| 运行日志 | 按功能、级别和关键词筛选，勾选导出或删除日志，并取消正在发送的任务 |
| 设置 | 切换主题、设置关闭时最小化到托盘与本次运行日志等级，确认后清除本地数据 |
| 关于 | 查看作者、仓库信息、版本信息和组件信息 |

## 目标地址

目标地址按 IPv4 四段分开填写，段间自动以 `.` 连接；前三段分别填写 0–255，最后一段支持单个末段、末段范围（如 `1-10`）和 `/24` 网段（如 `0/24`）。在四个地址输入框中按回车会依次跳到下一段，在最后一段按回车会进入端口输入框。

目标地址和 UDP 端口在文本消息、远程命令、设备操作与文件传送之间同步；发送轮数和轮次间隔仅在前三个远程页面之间同步。消息、命令及设备选择分别保留，切换页面不会清空草稿。窗口较窄时侧边栏会收窄为图标，窗口最小尺寸为 960 × 640。

## 文件传送

“文件传送”页面把本机勾选的文件或文件夹发送到目标电脑的当前用户桌面：

1. 填写目标 IPv4 地址、末段范围（如 `1-10`）或 `/24` 网段，也可选择设备备注；任务会按解析出的目标逐个传送。
2. 点击“添加文件”可一次选择多个文件，点击“添加文件夹”可添加整个文件夹；待传送列表以文件树展示，每个文件和文件夹都有复选框，列表标题栏第一格的复选框与行内复选框大小一致，用于全选或清空全部选择。
3. 新添加的文件和文件夹默认处于勾选状态。未勾选的条目平时显示文件或文件夹图标；鼠标悬停在名称列时，图标切换为复选框，离开后未勾选条目恢复图标。已勾选和部分勾选的文件夹持续显示复选框。
4. “传送文件”只传送当前勾选的文件；只勾选某个文件夹时，会传送该文件夹下的全部文件并保留目录结构。
5. 待传送列表顶部的删除按钮只移除勾选的文件或文件夹（不会删除源文件），未勾选任何条目时按钮不可用。
6. 点击“传送文件”，确认目标与文件后开始任务。目标端通过 Windows 自带的 `curl` 下载，进度显示在页面和运行日志中。
7. “文件传送”标题右侧的信息图标悬停后显示简要说明。

传送时 GUI 自动检测发送端 IP，并为每个目标启动一个仅在本机任务期间存在的随机令牌 HTTP 服务；界面不提供发送端 IP 输入框。检测会忽略 `198.18.0.0/15` 等虚拟或基准测试网段，并在出口地址不可用时选择与目标网段更接近的真实局域网地址。UDP 命令未得到响应时最多重发 3 次，避免单次丢包导致任务无响应。

目标电脑不需要开放入站端口，只需允许执行远程命令、提供 Windows 自带的 `curl.exe`，并允许其主动访问运行日志中显示的发送端 IP 与临时 TCP 端口。目标端不使用 PowerShell，因此不需要修改 PowerShell 执行策略。目标保存到当前登录用户桌面，不自动打开文件，也不会回传执行结果。运行日志中每个目标对应的“文件传送服务已启动”地址就是该目标需要访问的发送端 IP；失败信息会区分目标未访问文件服务、已取脚本但未下载，以及下载中断。任务可取消，取消或超时后会停止临时文件服务。

多个目标按顺序逐个传送，每个目标单独等待下载并显示当前目标进度。某个目标失败后会记录失败原因并继续尝试其余目标，全部目标处理结束后统一显示成功或失败结果；确认框会显示解析后的目标数量。`120` 秒超时按单个目标计算。

## 设备备注

“设备备注”页面用于把常用的 IPv4 地址映射为易读名称，标题右侧的信息图标悬停后显示备注用途和支持的地址格式：

1. 填写备注名和 IP 地址，点击“添加备注”。IP 地址同样分为四段，支持单个 IPv4、末段范围（如 `1-10`）和 `/24` 网段；备注名输入框按回车会进入地址第一段，地址最后一段按回车会保存。
2. 选中表格中的备注，可执行“设为当前目标”“修改”或“删除”；双击行也可直接修改。
3. 在任意远程页面点击目标地址右侧的“选择设备”，从弹窗的下拉列表中选择备注；目标地址四段会填入解析后的 IPv4，下方显示“备注名 → IPv4”的解析结果。
4. 修改备注名或 IP 后，当前目标如果引用该备注，会自动同步；删除正在引用的备注会清空当前目标。

备注名不区分大小写，不能为空、不能用纯 IP 格式，且同一名称只能对应一个地址或地址范围。备注可保存单个 IPv4、末段范围或 `/24` 网段；目标地址框仍可手动输入这些格式。备注与运行日志保存在程序所在目录的 `JiYuAttackNextData` 子文件夹中（源码运行时为项目根目录），重启 GUI 后仍会保留；该目录由 `.gitignore` 排除。只把 EXE 移到其他位置、不一起移动该文件夹时，会按默认配置启动。实际发送、确认框和设备预览始终使用解析后的地址，日志会记录备注名及解析结果。

## 运行打包后的 EXE

已构建的文件位于 `output\JiYuAttackNext.exe`，直接双击即可运行，无需安装 Python 或 PySide6。EXE 为单文件窗口程序，首次启动会解压运行时资源，可能需要数秒。

程序首次写入备注或日志时，会在 EXE 所在目录创建 `JiYuAttackNextData` 子文件夹，其中 `settings.ini` 保存设备备注，`runtime.log` 保存运行日志。若 EXE 所在目录不可写，备注和日志会保存失败并在界面提示；请将 EXE 放到可写目录后运行。

## 系统托盘与退出

- 第一次关闭主窗口时，程序会弹出一次提示，可选择“最小化到托盘”或“直接退出”；选择结果会保存到 `settings.ini`，之后关闭窗口不再重复询问。
- 选择“最小化到托盘”后，点击窗口关闭按钮会静默隐藏主窗口，不弹出托盘提示，后台任务继续执行；双击托盘图标或通过右键菜单选择“显示主窗口”可恢复界面。
- 托盘右键菜单中的“退出”会结束当前任务并真正退出程序。
- 在“设置”页的“关闭时最小化到托盘”选项中，可随时通过开关切换是否在关闭窗口时最小化到系统托盘。开关只显示状态，不显示附加文字。
- 如果系统托盘不可用，关闭窗口会直接退出程序。

## 界面行为说明

- 每个页面底部固定显示状态、日志入口、取消操作和当前页面的主操作按钮。任务在后台执行，可查看日志、请求取消；关闭时最小化到托盘会隐藏窗口并继续执行任务，首次提示选择“直接退出”、托盘菜单“退出”或关闭该开关时会先结束当前任务再退出。
- 消息支持多行和长文本自动分条。每条报文最多 448 个 UTF-16 单元，分条后的消息由接收端独立显示，脚本不负责合并或确认送达。
- 每个页面只发送当前页面的内容，避免切换页面后把不相关的草稿一起发送。重启与关机只能选择一项。
- 命令最多容纳 163 个 UTF-16 单元，界面实时显示使用量；超过容量会提示错误。
- “本机信息”和“防火墙”只操作运行程序的电脑，不向目标发送报文。防火墙操作需要管理员权限。
- 发送设备指令前会显示目标数量、端口和操作类型并要求二次确认。
- 反向 Shell 功能保留在 CLI 的 `-e nc` 中，GUI 不提供对应入口。
- 日志中的“发送完成”只表示本机发送调用完成，不代表目标已收到或执行成功。
- “关于”页顶部的图片与项目名称区域不绘制圆角卡片背景，标题下方依次显示与 [README](../../README.md) 首页一致的三行说明文字（工具定位、技术栈与授权提示）；下方依次显示作者卡片，以及“仓库信息”“版本信息”“组件信息”三张独立卡片。仓库信息合并主仓库与上游仓库两个链接；版本信息合并版本与构建时间；组件信息列出 PySide6 与 Fluent Widgets 的版本。三张卡片的行高统一，超链接行与文本行的行距一致。构建时间取自打包时写入的构建时间标记，源码运行时显示“源码运行”；版本号在 EXE 中取自打包时写入的版本，源码运行时显示 `app/__version__`。
- 程序同一时间只允许运行一个实例（含托盘中的隐藏窗口）。再次启动 EXE 时不会打开第二个窗口，而是唤醒已运行的主窗口并置于前台。
- “设置”页底部的“清除数据”会先显示确认框；确认后删除程序数据目录（包括设备备注、界面设置与运行日志），取消则不做修改。清除后关闭窗口行为恢复为默认的最小化到托盘，首次关闭提示也会重新出现；本次运行的文件日志暂停，重启程序后恢复写入。
- 运行日志默认以 `INFO` 等级运行，可在“设置”页的“运行日志等级”下拉框中切换为 `DEBUG`、`INFO`、`WARNING` 或 `ERROR`。运行等级是写入阈值：选择 `WARNING` 后，新的 `DEBUG`、`INFO` 记录不会进入列表和日志文件；本次运行结束后不会持久化该设置。
- 日志页提供两级筛选：“全部功能”按功能分类筛选，“全部级别”按 `DEBUG`、`INFO`、`WARNING`、`ERROR` 精确筛选，搜索框会在时间、级别、功能、内容、线程和输出位置中匹配关键词。多个筛选条件同时生效。
- 日志表每行带复选框，可多选；表头第一格（时间列之前）同样带复选框，用作全选：勾选表头会选中当前筛选结果，任意一行取消勾选后表头自动取消，取消表头会清空全部选择（包括被筛选条件隐藏的行）。批量操作只能针对已勾选的记录。
- 日志页上方的导出和删除按钮只作用于勾选记录：导出按规范文本导出选中日志，删除在确认后删除选中记录并同步重写日志文件；没有勾选记录时两个按钮均不可用。
- 运行日志在启动时从 `runtime.log` 载入最近 2000 条记录，新记录实时追加。格式为 `2026-10-23 12:34:56.789 [12345] [MainThread] INFO    app.gui.app.MainWindow:123 - [文本消息] 开始发送：192.168.1.20，端口 4705，1 轮`，多行内容与异常堆栈以缩进续行写入；旧版 JSONL 日志会自动读取并迁移为规范文本。
- 日志字段包括毫秒级本地时间、线程 ID、线程名称、级别、输出模块与行号、功能分类、消息和可选详情。异常会记录异常消息与 Python 堆栈，便于复现和定位问题。
